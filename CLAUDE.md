# Change documentation

Whenever you make a change to this project (features, fixes, content, config — anything a user asks for or you implement), append a dated entry to `changes.md` at the project root summarizing what changed and why, in plain language a non-technical manager can follow. Group same-day changes under one `## YYYY-MM-DD` heading (today's date), newest date at the top, newest entry within a day at the top of its section. Keep each entry a short paragraph — what changed, why it mattered, no code snippets or file-path-level detail. Do this automatically, without being asked, at the point a change is complete and verified — don't wait for the user to request it.
